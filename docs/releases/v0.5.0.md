# OpenTranscribe v0.5.0 — Open-Core Foundations, Boundary-Accurate Diarization, Content Redaction & a Complete Backup Story

Our largest release to date: **400+ commits since v0.4.1**.

⚠️ **This release contains breaking changes** — read the Upgrade Notes below before updating.

## Highlights

- **Boundary-accurate diarization (#193)**: default-on word-boundary smoothing (−32% relative word-speaker-error-rate on the reference clip, wrong-speaker islands 82 → 15) plus an optional acoustic backchannel re-check (further ~−15%). Benchmarked against six commercial engines, the local pipeline ties the best commercial accuracy (0.27% WSER) at ~41× realtime. Live-tunable from the admin Engine panel.
- **Content redaction**: PII / profanity / toxicity detection (Presidio, NER, toxicity classifiers, wordlists, optional LLM) on a new dedicated `celery-redaction` CPU worker; read-time `[CATEGORY]` masking across display, search, exports, and LLM prompts — originals always preserved. Per-user settings + an admin enforcement floor.
- **Complete backup story**: in-app scheduled DB backups (GFS retention, optional GPG) to folder or S3 · OpenSearch snapshots · a GPG-encrypted **recovery-key companion** so a backup destination is restore-sufficient · an incremental, **never-deleting media mirror** to a separate destination · Prometheus metrics + admin alerts on failures · `reingest_minio` disaster recovery for orphaned media.
- **Watch sources (#26)**: auto-ingest from local folders, S3 buckets, or SMB shares — polling, 3-layer content dedup, multi-part recording stitching, optional email notifications, all configured live in the admin UI.
- **Presigned media pipeline**: uploads go browser→storage directly (content-hash dedup, magic-byte validation); playback/downloads stream from storage via short-lived presigned URLs with SSE progress and async bulk export.
- **Transcription engine**: combined engine with optional multi-GPU split, hybrid mode (CPU transcribe + GPU/MPS diarize) for small GPUs and Apple Silicon, model-aware VRAM tuning, and a ~5 GB slimmer backend image. Measured with the new `./opentr.sh bench` suite: **45.9× aggregate realtime** on one RTX A6000, **81.3×** on two (58-hour corpus in ~43 minutes).
- **Open-core foundations**: generic extension seams (external-auth registry, quota/metering hooks, capabilities + per-tenant resolvers) and organization-scoped isolation across SQL/search/voiceprint planes — **inert no-ops in the community edition**, with a CI gate guaranteeing zero vendor names in this codebase. The hardening benefits everyone: real GDPR Art. 17 erasure, a DMCA takedown flow with §512(g) owner notices, org-scoped audit reads, and a unified role-based privilege model with a local-only super-admin tier.
- **Observability**: Prometheus `/metrics`, structured JSON access logs with request-ID→Celery propagation, readiness probe, optional Grafana overlay with prebuilt dashboards.
- **Verified cloud ASR**: AWS Transcribe, Speechmatics, AssemblyAI, Gladia, and pyannote.ai all tested end-to-end; CrisperWhisper model support.

## Breaking Changes

1. **Removed byte-proxy media endpoints** — `GET /api/files/{uuid}/video`, `/simple-video`, `/content`, `/download`, `/download-with-token`. Use `GET /api/files/{uuid}/stream-url` (playback) and `POST /api/files/{uuid}/prepare-download` (downloads). Presigned URLs support range requests; seeking is unaffected.
2. **Bulk export** — synchronous `POST /api/files/bulk-export` replaced by `POST /api/files/bulk-export/prepare` + SSE `GET /api/files/bulk-export-stream`.
3. **File fingerprints regenerate once** — server-side `imohash` now uses the real imohash package; an automatic one-time recompute runs on first startup (cross-pipeline dedup unreliable until it finishes).
4. **New required service** — the `celery-redaction` worker (included in standard compose overlays; no action needed with `./opentr.sh` or the installer).
5. **Migration v367 rewritten** (vendor-neutral columns) — affects only deployments tracking unreleased master; repaired automatically by v371 on startup.

Migrations v360–v373 apply automatically on backend startup — no manual alembic step.
