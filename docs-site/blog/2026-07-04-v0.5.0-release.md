OpenTranscribe v0.5.0 is our largest release to date: 400+ commits since v0.4.1 spanning a vendor-clean open-core architecture, measurably better speaker diarization at turn boundaries, PII/profanity/toxicity redaction across every surface, automatic watch-folder ingestion, a presigned-URL media pipeline, and a backup system that now covers everything — database, search indices, encryption keys, and the media files themselves.

**This release contains breaking changes** — see the Upgrade Notes below before updating.

## Highlights

### Diarization that gets turn boundaries right (issue #193)

Speaker mislabeling at turn seams — the classic "yeah" attributed to the wrong speaker — drops dramatically in v0.5.0:

- A **default-on word-boundary smoother** collapses 1–3-word wrong-speaker islands, guarded by silent-gap and flanking-speaker checks. On the hand-labeled clip from the original report: **−32% relative word-speaker-error-rate, wrong-speaker islands 82 → 15**.
- An optional **acoustic backchannel re-check** (experimental, GPU) re-embeds short disputed words by voiceprint and recovers absorbed backchannels for a further ~−15%, at ~1.9 s per 10-minute file.
- Benchmarked against six commercial engines (Deepgram, AssemblyAI, Gladia, Speechmatics, AWS Transcribe, pyannote.ai), the local smoothed pipeline **ties the best commercial accuracy (0.27% WSER) at ~41× realtime** — on your own hardware, with your data never leaving it.

Both stages are tunable live from the admin Engine Configuration panel — no restarts.

### Content redaction: PII, profanity, and toxicity

Detection runs once per transcript on a new dedicated CPU worker (Presidio + NER for PII, dedicated toxicity classifiers, wordlists, optional LLM) and caches spans on the segments. Masking is a **read-time transform** — the original transcript is always preserved — applied across display, search snippets, SRT/VTT/TXT exports, and LLM prompts. Per-user settings (on by default, with live preview) plus an **admin enforcement floor** that can mandate categories and censored exports org-wide.

### A complete backup story

- **In-app scheduled database backups** (admin-configured cron, GFS retention, optional GPG encryption) to a mounted folder or any S3-compatible bucket — no host cron.
- **OpenSearch snapshots** ride the same schedule and retention.
- **Recovery-key companion**: encrypted backups now include a GPG-encrypted copy of the essential keys (`ENCRYPTION_KEY`, `JWT_SECRET_KEY`) beside the dumps — a destination is finally restore-sufficient on its own. Unencrypted destinations get a recovery README and a one-time admin warning instead of plaintext keys.
- **Media Mirror**: incremental, never-deleting copies of the media bucket itself to a separate destination (folder or S3) — closing the last high-severity gap in the backup audit. Deletes never propagate, so a fat-fingered or malicious source-side delete can't reach your mirror.
- **Proactive failure surfacing**: Prometheus metrics (`backup_last_success_timestamp_seconds`, `backup_runs_total{result}`, mirror equivalents) and admin notifications on any failed run.
- **Storage recovery**: `reingest_minio` re-registers orphaned MinIO objects in place (zero bytes copied) and runs them through the standard pipeline — born from a real disaster-recovery incident, now a supported tool.

### Watch sources: automatic ingestion (issue #26)

Point OpenTranscribe at a **local folder, S3-compatible bucket, or SMB/CIFS share** and it polls, dedupes (3-layer content fingerprinting), imports, and transcribes new media automatically — including multi-part recording stitching (ffmpeg) and optional email notifications. All configuration is live in the admin UI.

### Faster, leaner media pipeline

- **Presigned direct-to-storage uploads** with content-hash dedup and magic-byte validation; a shared-memory WAV handoff between pipeline stages; end-to-end timing instrumentation.
- **All media playback and downloads now stream directly from object storage** via short-lived presigned URLs (range-capable — seeking works), with SSE progress and async bulk export. The old byte-proxy endpoints are removed (breaking — see Upgrade Notes).
- A combined transcription engine with optional **multi-GPU split** and **hybrid mode** (CPU transcription + GPU diarization) for small-VRAM GPUs and Apple Silicon; the backend image slimmed by ~5 GB.

### Open-core foundations & multi-tenant hardening

v0.5.0 lands generic, open extension seams — a pluggable external-auth verifier registry, pipeline quota/metering hooks, a capabilities resolver, per-tenant limit resolvers, and organization-scoped data isolation across SQL, search, and the speaker/voiceprint planes. In the self-hosted community edition these are **inert no-ops with zero overhead**: no orgs, no behavior change. They exist so a managed edition can layer on top **without a single vendor name in this codebase** — a CI gate greps the entire backend and frontend source and fails the build if one appears.

Along the way this work hardened the platform for everyone: GDPR Article-17 erasure that actually cascades (storage + rows + biometric voiceprint docs), an abuse/DMCA takedown flow with owner notification and counter-notice instructions per §512(g), organization-scoped audit reads, and dozens of authorization-surface fixes found by adversarial review.

### Observability

Prometheus `/metrics` (request histograms, per-request DB query counts, queue depths, product counters), structured JSON access logs with request-ID propagation into Celery, a readiness probe, and an optional Grafana overlay with prebuilt ops and product dashboards.

## Breaking changes & upgrade notes

1. **Removed media endpoints**: `GET /api/files/{uuid}/video`, `/simple-video`, `/content`, `/download`, `/download-with-token` → use `GET /api/files/{uuid}/stream-url` (playback) and `POST /api/files/{uuid}/prepare-download` (downloads).
2. **Bulk export**: `POST /api/files/bulk-export` → `POST /api/files/bulk-export/prepare` + SSE `GET /api/files/bulk-export-stream`.
3. **File fingerprints regenerate once** on first startup (real `imohash`); cross-pipeline dedup is unreliable until the automatic recompute finishes.
4. **New required service**: the `celery-redaction` worker (included in the standard compose overlays — no action with `./opentr.sh` / the installer).
5. **Migration v367 was rewritten** (vendor-neutral columns). No tagged release shipped the old shape; deployments tracking unreleased master are repaired automatically by v371 on startup.

All migrations (v360–v373) apply automatically on backend startup.
