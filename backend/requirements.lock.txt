# Why this exists
# ---------------
# `requirements.txt` is 61 floors against 4 exact pins, and a floor is a version
# number but not a pin: `nltk>=3.9.4` permits 3.9.4 OR 3.10.3. Two installs done at
# different times legitimately resolved differently, and did — 120 packages apart,
# 18 at a MAJOR version (starlette 0.48 vs 1.6, openai 2.44 vs 3.2, pandas 2.2 vs
# 3.0). The gate ran against one set and production ran the other.
#
# That is not hypothetical: it is how the NLTK `pathsec` breakage reached
# production unseen. `nltk>=3.9.4` gave the venv 3.9.4 and the image 3.10.3, and
# 3.10 refuses multiply-linked files — so `split_sentences_nltk` raised on every
# call in the backend and both transcription workers while the host suite passed.
# The gate was structurally incapable of seeing it.
#
