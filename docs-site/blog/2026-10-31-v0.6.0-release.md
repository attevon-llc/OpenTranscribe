OpenTranscribe v0.6.0 is about polish and trust. The interface got a thorough refresh, Settings now tells you what will happen before it happens, a speaker's name only comes from a person or a voiceprint match, transcription and speaker detection can be mixed and matched, local or cloud, and the voiceprint and gender features now have switches you control. It is a standard upgrade: back up, update, and the database migrates itself when the backend starts.

## A Refreshed Interface

We ran the whole app past a UX review and then two consistency passes, and fixed what they found. Every dialog now shares one modal, every input one style, every slider one design, and the date-range picker is a popover shared by the gallery and file status. Type is lighter, there is one accent colour, and every menu item has an icon.

- **Gallery:** a two-row toolbar, a filter panel you can collapse and type dates into, a filter by owner, and one status indicator for grid and list that is never clipped.
- **File page:** organized around editing speakers, with comments under the transcript and a *Jump to current playback position* button in place of the minimap that could rewind playback.
- **Search:** a full-width query bar, details you can pin, collections shown on results, and matches you can collapse. See [Search and filters](/docs/user-guide/search-and-filters).
- **Navigation:** Gallery, Transcript Search, AI Chat, Speakers. File status moved into Settings.
- **Notifications:** each file's card shows its stages in three tiers (Main processing, Finishing, AI enrichment) and only finishes when post-processing is really done. Downloads get one live row, finished jobs say how long they took, and the panel clears routine items on its own, on a retention policy you choose. See [Notifications and the About dialog](/docs/user-guide/notifications-and-about).
- **Faster:** the app loads a fraction of the code it used to at startup, Settings opens instantly and loads each section on demand, and rate limits tell you exactly how long to wait.

## Settings That Say What They Will Do

Transcription and Speaker Identification are now separate tabbed sections, Privacy and Redaction are one, and data tools live together under Data & Storage. The new **Processing pipeline** page shows, before your next upload, where each step will run, which providers will receive the audio, and anything that would stop it, with a link to the tab that fixes it.

## Speakers You Can Trust

A speaker's name in search, chat, summaries and exports now comes from a person or from a voiceprint match at 75% similarity or more. AI speaker-name suggestions are still made and offered with their confidence, but they no longer become the name on their own. After upgrading, labels that only ever came from an AI guess return to `SPEAKER_01` and friends until you accept a name; this happens in the background, no reindex needed. Each speaker's identity also records whether it came from a person or a voice match, so you can always tell which is which.

Corrections stick, too. Unassigning a speaker from a cluster now means "this voice is not that person": no automatic path puts it back, and the correction survives re-transcribing the file. Removing a speaker removes every copy of its voice from clusters and profiles. And you can now name a speaker straight from the transcript's speaker menu.

## Privacy Controls for Voiceprints and Inferred Gender

Recognizing the same person across recordings, and inferring a speaker's gender from their voice, both work on biometric-style data. Each now has a switch, and the switches are restrict-only: the instance, the organization (managed edition) and each person can turn a feature off, and if any layer is off, the feature is off. If the policy cannot be read, the answer is "off".

Turning a switch off hides existing data and stops new data, and deletes nothing. Speakers are still told apart within a recording. Deleting is a separate action: an explicit purge with a typed confirmation, recorded in the audit log, that reports how many items it removed from each store and checks afterwards that nothing from the deletion remains. Both switches default on, so an upgrade deletes or rewrites nothing; the one exception is that anyone who had already turned inferred gender off in Voice Attributes now has stored inferred genders hidden everywhere, and genders a person confirmed are always kept. Wherever gender is shown, the interface says it is inferred automatically from voice and links to the switch ("Change in settings"). The switches live under **Settings, Privacy & Redaction**; the full reference, including the purge and the API, is in [Privacy controls](/docs/features/privacy-controls).

## A Pipeline You Compose

Transcription and speaker detection are now two independent choices, each local or cloud, and one resolver plans every run. Local Whisper with pyannote.ai speaker detection works, as does using another provider's speaker detection with any transcription. Every file now records which provider and model completed each step, shown in a new **Processing** section on the file page.

A super admin can also manage the local models: download any Whisper model on the shipped list from **Settings, Transcription, Local models** with a disk-space check, live progress and cancel, then switch the active one. Only the Whisper workers restart, and only after running jobs finish. A super admin can also limit which cloud transcription providers plain users may choose. See [Local transcription models](/docs/features/local-transcription-models).

The lite image (no GPU) is now cloud-only for transcription and speaker detection, with voiceprints still computed on your server. [Deployment variants](/docs/installation/deployment-variants) lists every valid combination, generated straight from the code.

## Export in the Format You Need

The transcript Export menu now covers TXT, JSON, CSV, SRT, VTT and Markdown, plus **Word (.docx)** and **PDF**. Word and PDF are built on the server with numbered lines you can cite by page and line, right-to-left layout for Arabic and Hebrew, and shaping and wrapping for CJK and other scripts. The redaction policy is applied when the document is built, so it cannot be bypassed from the browser. The Markdown export adds YAML front matter for note-taking tools. See [Document export](/docs/features/document-export).

Captions are cut on the server with broadcast rules: two lines, comfortable reading speed, a speaker's name at the start of each turn, and line breaking that respects Japanese, Thai and other scripts. The same captions drive the player, subtitle downloads and burned-in video, so what you watch is what you export.

## Organizations, Audit and Legal Holds (Managed Edition)

The managed edition gains tools for teams that need governance. These surfaces are switched off in the open-source build, which ships the capability gates but not the organization features.

- **Restricted collections:** an organization collection can be limited to its creator, the organization's admins and the people it is shared with. Everyone else sees it as not found.
- **Legal holds:** an organization admin can hold files, or a whole collection. A held file cannot be deleted, purged by retention, erased with an account or reprocessed, and the hold is audited.
- **Audit log:** the organization's own events, filterable by member, event, outcome, dates or a file or collection, with a CSV or JSON export.
- **Takedown queue:** organization admins can quarantine and release their own files, and owners can see why a file was taken down and how to dispute it.

Everyone gets two related improvements. A super admin can switch on content-access auditing (who opened a recording, requested its media, or exported a transcript; off by default), and quarantining a file now writes a durable record of the notice it acts on. Tags and collections also belong to one organization where organizations are in use, and administrators in multi-tenant installs use audited, time-boxed support-access grants instead of opening tenant content directly. See [Support access](/docs/operations/support-access).

## Reliability and Data Integrity

- **Task recovery:** recovery no longer fails or duplicates transcriptions that are waiting for a GPU, a stale "in progress" task row is retired once a newer one supersedes it, and a file is never stranded or failed because its worker died.
- **GPU work** is admitted by available VRAM and host memory, and recovers from out-of-memory errors.
- **Data integrity:** find and remove orphaned search documents and stored files from the admin UI, and a delete now leaves nothing behind in any store. Durations are a recording's real length again, and search indexing retries until a file is searchable.
- **Search quality, honestly reported:** the chat reranker's CPU thread count is now configurable and shown in System Statistics. How much reranking helps answer quality is still being measured; the numbers, including the ones that are unflattering, are in [RAG evaluation](/docs/developer-guide/rag-evaluation).

## Security and Dependencies

- **Hardened tenant boundaries:** in multi-tenant installs, tags, collections, shared prompts, shared settings and speaker data are checked against the caller's organization in each layer that reads them.
- **Dependencies:** `transformers` moves to 5.10.4 and `nltk` to 3.10.4 (the backend now keeps its `nltk_data` tree private, as that release requires). Release images are rebuilt with refreshed OS packages and scanned before they are published.
- **Sign-in:** NIST SP 800-63B-4 password levels, an optional breached-password list, idle and absolute session timeouts for external sign-in, stricter browser security headers, and third-party telemetry off by default.

## In Every Language

Every new string ships in all 12 languages, the English source copy was rewritten so it translates cleanly, admin strings that had slipped through in English were translated (with a test so it cannot happen again), and native-level reviewers checked each locale.

## Upgrading

The upgrade is standard. Back up first:

```bash
./opentranscribe.sh backup
./opentranscribe.sh update
```

The database migrations run automatically when the backend starts, and they are one-way, so the backup is your way back. A few behaviours are different afterwards: AI-only speaker labels, unassignment, `ENABLE_DIARIZATION`, lite, tenancy mode, notification retention, and Amazon Transcribe now requires `AWS_TRANSCRIBE_BUCKET`. [Upgrading to 0.6.0](/docs/operations/upgrading-to-0-6-0) walks through each one and what, if anything, to do.
