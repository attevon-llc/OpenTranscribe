OpenTranscribe v0.5.0 is our largest release to date. It lands four major feature areas — **diarization boundary correction**, **content redaction**, a **production-verified cloud ASR suite**, and a **rebuilt media download architecture** — on top of a substantial pipeline overhaul and a wave of security and operations hardening.

**This release contains breaking changes.** Read the [Upgrade Notes](#upgrade-notes) before pulling.

## Diarization Boundary Correction

Speaker diarization has always been strongest in the middle of a turn and weakest at the seams. When one speaker stops and another starts, the boundary rarely lands on the word — it lands a few hundred milliseconds early or late, and a word or two gets attributed to the wrong person.

v0.5.0 ships two independent corrections for this:

- **Word-boundary smoother (default ON)** — snaps speaker boundaries to word edges rather than raw diarization timestamps. Measured **−32% word-level speaker error rate (WSER)**.
- **Acoustic backchannel re-check (default OFF, experimental)** — re-examines short interjections ("mm-hmm", "right", "yeah") that diarizers routinely mis-assign. A further **−15%** on top of the smoother.

Both are controlled from the admin UI with no restart, and both are documented in detail under [Diarization Boundary Correction](/docs/features/boundary-correction).

## Content Redaction

A new redaction subsystem detects **PII, profanity, and toxicity** and applies masking at read time across every display and export surface — transcript view, search results, summaries, subtitles, and downloads.

The design is deliberately *detect-once, cache-forever*: detection runs exactly once per transcript on a dedicated `celery-redaction` CPU worker, and the results are cached. Redaction is then applied when content is read, which means a user's redaction preference can change without reprocessing anything.

Users can opt out of their own redaction; administrators can set an enforcement floor that individual users cannot drop below. Unredacted views are audited.

**This adds a required service.** Deployments must run the `celery-redaction` worker — it is already in the standard compose overlays, so `./opentr.sh` users need no action.

## Cloud ASR Providers: Now Verified

The cloud ASR providers introduced as experimental stubs in v0.4.0 are now **tested end-to-end and production-verified**: AWS Transcribe, Speechmatics, AssemblyAI, Gladia, and pyannote.ai.

Worth stating plainly, because it surprised us: our **local smoothed pipeline reached 0.27% WSER at 41× realtime**, which ties the best commercial engine we benchmarked. Self-hosting is not the accuracy compromise it is often assumed to be.

## Media Download Architecture

Media no longer streams through the API. Playback and downloads now use short-lived **presigned MinIO URLs**, with SSE progress reporting and an async worker for bulk exports.

This removes the backend as a bandwidth bottleneck entirely, and presigned URLs support HTTP range requests natively, so video seeking is unaffected. **The legacy byte-proxy endpoints have been removed** — see Upgrade Notes.

## Backups That Cover the Irreplaceable Parts

Scheduled database backups are now configured entirely from the admin UI — no host cron, no new environment variables, no new Python dependencies. Cron schedule, GFS retention (7 daily / 4 weekly / 12 monthly), optional GPG encryption, and a Run Now button.

Two details matter more than the scheduling:

- **A database dump alone is unrecoverable.** Its AES-256-GCM ciphertext needs the `.env` master keys that wrote it. Every successful run now makes the destination self-describing — with encryption on, an `opentranscribe-recovery.env.gpg` companion lands beside the dumps under the same passphrase.
- **Media Mirror (default OFF)** incrementally copies the MinIO media bucket to a *separate* destination. It **never deletes at the destination**, so a fat-fingered or malicious source-side delete cannot propagate. That is an explicit, tested invariant.

## Observability

A root-mounted `/metrics` endpoint (internal-network only) exposes request latency by route template, error rates, Celery queue depth, and **per-request DB query counts** — the last of which makes N+1 queries visible per endpoint rather than requiring a profiler.

Every request emits a structured access log line carrying `user_id`, `org_id`, `request_id`, and `db_query_count`, and request IDs propagate into Celery tasks so API calls and their background work correlate. An optional Prometheus + Grafana overlay ships two prebuilt dashboards: `./opentr.sh start dev --with-monitoring`.

## Fresh Deployments and Data-Safety Guardrails

`./opentr.sh start dev --fresh <name>` creates a throwaway deployment in its own compose project with its own containers *and* named volumes. The NAS/bind storage overlay is **never** loaded in fresh mode, so an experiment physically cannot touch real data.

Complementing that, every NAS-overlay start now writes a `.opentranscribe-live-data` marker into each bind-mounted directory, and `./opentr.sh data-paths` prints exactly which host paths hold live data — so you can check before any cleanup, not after.

## Documentation Site Overhaul

The docs site got a correctness and mobile pass in this release.

**The version badge was wrong.** The homepage hard-coded `v0.4.0` and had drifted a full release behind. It now reads the repository's `VERSION` file at build time, so it cannot disagree with what actually shipped — and a `VERSION` bump now triggers a docs redeploy.

**The homepage scrolled sideways on every phone.** Roughly 200px of horizontal overflow on a 375px viewport, caused by two independent flexbox bugs: the hero install command and the comparison table were both centered flex items whose default `min-width: auto` stopped them shrinking, pushing their left edges off-screen where no amount of scrolling could reach them. Both are now proper scroll containers. Horizontal overflow is 0px at every viewport from 375px through 1440px.

**Wide tables are now genuinely usable on a phone.** The 12-column comparison table scrolls with its "Feature" column pinned, so a checkmark in the rightmost column is still attributable to its row. Every markdown table across the docs is wrapped in a scroll container with edge-fade affordances — replacing Infima's default, which scrolled but stripped table semantics for screen readers. Tables are real tables again, and only genuinely scrollable ones become keyboard tab stops.

Finally, broken links now **fail the build** rather than shipping, repository links follow the [move to Attevon LLC](/blog/opentranscribe-joins-attevon), and a couple of blog posts that linked a never-registered domain now point at the live one.

## Upgrade Notes

- **Breaking — removed media endpoints.** `GET /api/files/{uuid}/video`, `/simple-video`, `/content`, `/download`, and `/download-with-token` are gone. Migrate to `GET /api/files/{uuid}/stream-url` for playback and `POST /api/files/{uuid}/prepare-download` for downloads.
- **Breaking — bulk export.** `POST /api/files/bulk-export` is replaced by `POST /api/files/bulk-export/prepare` plus the SSE `GET /api/files/bulk-export-stream`.
- **Breaking — file fingerprints regenerate.** The server-side fingerprint now uses the real `imohash` package instead of a hand-rolled stand-in, so **every existing value changes**. A one-time recompute runs automatically on first startup — no manual action required. Cross-pipeline dedup is unreliable for not-yet-recomputed rows until it finishes.
- **New required service.** Deployments must run the `celery-redaction` worker. Included in the standard compose overlays.
- **Migrations** `v360` through `v373` apply automatically on backend startup (idempotent, additive).
- **New environment variables are all optional** with sensible coded defaults. Note that many settings that look like they need `.env` entries are actually DB-backed and edited live in the admin UI.

Full detail is in the [CHANGELOG](https://github.com/attevon-llc/OpenTranscribe/blob/master/CHANGELOG.md).
