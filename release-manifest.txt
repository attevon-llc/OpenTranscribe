# release-manifest.txt — the files a self-hosted deployment needs.
#
# ONE list, consumed by three things that used to keep their own:
#   * setup-opentranscribe.sh  (fresh install: downloads each of these at the pinned ref)
#   * opentranscribe.sh update-full  (existing install: re-downloads each of these)
#   * .github/workflows/release-validate.yml  (asserts every path is fetchable at the tag)
#
# WHY THIS FILE EXISTS
#
# The installer and update-full each hardcoded their own list, and the lists had
# drifted apart in both directions:
#
#   * update-full never re-downloaded docker-compose.yml. Service *definitions*
#     live in the base file — the prod overlay only adds image/volumes. So when
#     celery-redaction was introduced (its `command:` exists only in
#     docker-compose.yml), an upgraded install merged the prod stanza into a base
#     file that had no such service and started the container with the image's
#     default CMD instead of the redaction worker. Silently.
#
#   * setup-opentranscribe.sh never downloaded docker-compose.blackwell.yml, but
#     opentranscribe.sh's get_compose_files() selects it when it detects an SM_12x
#     GPU. The selection is guarded by `[ -f ... ]`, so a fresh install on a
#     Blackwell card silently fell back to the generic GPU overlay — i.e. ran
#     :latest instead of the :blackwell image that exists precisely because the
#     generic one does not work on that hardware.
#
# Both are the same bug class: a deployment file list maintained in more than one
# place. Adding a file to a deployment is now a one-line change here.
#
# FORMAT
#   <repo-relative-path>[<TAB>flag,flag]
# Flags:
#   optional  — a 404 is not fatal (file may not exist in older releases)
#   exec      — chmod +x after download
#   preserve  — never overwrite an existing copy (user-owned data)
# Blank lines and #-comments are ignored.

# --- Compose: base + every overlay a deployment can select ---------------------
# docker-compose.yml is FIRST and is not optional: it carries the service
# definitions every overlay merges on top of.
docker-compose.yml
docker-compose.prod.yml
docker-compose.gpu.yml
docker-compose.gpu-scale.yml
# Optional overlay for multi-GPU SPLIT: transcription and diarization on separate host
# GPUs, gated on ENGINE_GPU_SPLIT=true (opentranscribe.sh's gpu_split_active(), issue
# #708). `optional` because it only benefits a 2+ GPU host and most installs never set
# the gating var — unlike docker-compose.gpu-scale.yml above, which every single-GPU
# install can benefit from and is therefore required. Before this entry, a self-hosted
# install could never download this file at all: get_compose_files() had no reference
# to gpu-split, so setting ENGINE_GPU_SPLIT=true routed dispatch onto queues nothing
# consumed (issues #703/#705 fix what happens there; this is what makes their fix
# reachable outside `opentr.sh` dev).
docker-compose.gpu-split.yml	optional
docker-compose.blackwell.yml	optional
docker-compose.nginx.yml
docker-compose.backup.yml	optional
# The native (Rust/ONNX) diarization sidecar. `engine.diarizer_backend` defaults to
# `native`, so without this overlay a deployment silently serves every file from the
# in-process PyAnnote fallback instead (issue #639). The diar-server binary already
# ships inside the backend image; the ONNX/PLDA weights are exported locally from the
# operator's own gated HuggingFace access, exactly as the PyAnnote weights are.
#
# NOT `optional` any more (issue #670). An optional entry that 404s during `update-full`
# is reported as a yellow "(optional, not in this release)" line and the upgrade
# continues — which, for the overlay that carries the DEFAULT diarization engine, means
# a transient network blip silently downgrades an install to the fallback with no error
# anywhere. Required is the honest description: the engine is not optional, only the
# fallback is.
#
# Selection is no longer gated on the weights already existing. The backend exports them
# from its FastAPI lifespan (app/transcription/native_provision.py), so gating on them
# beforehand cost a fresh install two starts to converge; the gate is now "engine is
# native AND (weights present OR a HuggingFace token is configured)" — the token being
# what makes the export possible.
docker-compose.diar-native.yml
# The GPU reservation for that sidecar, split into its own file so the overlay above is
# safe to load on a CPU-only or --lite host with no nvidia runtime. Loaded alongside
# docker-compose.gpu.yml; it also flips DIAR_MODE from the CPU-safe default to `cuda`.
docker-compose.diar-native-gpu.yml
# Opt-in RAM-backed override for the `pipeline_scratch` cross-worker WAV handoff volume
# (issue #661 E5; see backend/app/utils/scratch_volume.py). `optional` — this is a
# performance knob for RAM-rich hosts, never required, and the base compose file already
# references it by name so a fresh install that skips it just keeps the disk-backed
# default. Load with `./opentr.sh start dev --with-scratch-tmpfs`.
docker-compose.scratch-tmpfs.yml	optional
