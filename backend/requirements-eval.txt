# Retrieval-evaluation dependencies — TEST/EVAL ENVIRONMENT ONLY.

# Dockerfile. This is a LICENCE boundary, not tidiness.
#
# `pytrec_eval_terrier` is MIT for the Python wrapper, but the wheel embeds the
# NIST trec_eval C sources, several of which (trec_eval.c, m_ndcg.c,
# m_ndcg_cut.c, m_recip_rank.c — read, verbatim) carry:
#
#     Copyright (c) 2008 - Chris Buckley.
#     Permission is granted for use and modification of this file for
#     research, non-commercial purposes.
#
# GitHub reports NOASSERTION for usnistgov/trec_eval for exactly this reason.
# Computing measurements for research and for a paper is squarely inside that
# grant. **Redistributing** it inside davidamacey/opentranscribe-* images, which
# ship a product with a commercial edition, is not. So it lives here, installed
# by the eval path only.
#
#   backend/venv/bin/pip install -r backend/requirements-eval.txt
#
# Cost, measured in a clean venv: a 1.1 MB compiled extension plus ~32 KB of
# Python, declaring only numpy and scipy — both already installed (numpy pinned
# in requirements.txt, scipy transitively via sentence-transformers).
# Net new transitive dependencies: ZERO. Verified again on install here.
#
# Rationale and the measured 0.369 absolute nDCG@10 divergence between
# implementations that made this a decision rather than a preference:
# .rag-403/oss-leverage-survey.md §1 and
# docs-site/docs/developer-guide/rag-evaluation.md.

# NIST trec_eval, wrapped. The maintained fork (Glasgow / Terrier team) —
# publishes wheels; the original cvangysel/pytrec-eval is sdist-only and last
# released in 2020.
pytrec_eval_terrier>=0.5.10

# Canonical measure strings ("nDCG@10", "R@10") with explicit provider naming,
# so a label in a table is checkably the measure trec_eval computed. Base
# dependency: pytrec-eval-terrier only. Its optional providers (ranx, trectools,
# cwl_eval) are extras and are deliberately not installed.
ir_measures>=0.4.3

# Answer-quality tier (issue #463, W2/A2). Deterministic-floor packages below
# this line are SAFE — verified by `pip install --dry-run` against this exact
# venv to add ZERO conflicting transitive pins (rouge-score/bert-score/nltk:
# only `absl-py` new, everything else already satisfied by the app's own
# torch/transformers/matplotlib/requests stack). `backend/CLAUDE.md` (#492):
# "every spec is pinned, a floor is not a pin" — `nltk` below is pinned to the
# exact version `requirements.txt` already resolves (3.10.3), not a new floor.

# rougeLsum + a Porter stemmer, matching the summarization-eval convention
# (`use_stemmer=True`, longest-common-subsequence over SENTENCES for rougeLsum).
rouge-score==0.1.2

# BERTScore (MIT). Pinned model in every call site, never left to the
# package's own moving default: `microsoft/deberta-large-mnli`,
# `rescale_with_baseline=True`, `lang="en"` (QMSum is English-only; see
# rag-evaluation.md's multilingual coverage table for why this is not a
# silent scope narrowing). `answer_text.py`'s bertscore_f1 is optional and
# `pytest.importorskip`-gated for the same licence-adjacent reason the metric
# engine above is: not a licence issue here, but a genuinely heavy optional
# dependency (torch + transformers, both already required by the app, but a
# multi-hundred-MB model download on first use) that must never become a hard
# import for the deterministic floor.
bert-score==0.3.13

# Already a hard `requirements.txt` pin (nltk==3.10.3, the #492 NLTK
# `pathsec`-hardening version) — repeated here, at the SAME version, only so
# this file's own dependency list is self-describing without cross-reading
# requirements.txt. Never bump this independently of requirements.txt's pin.
nltk==3.10.3
